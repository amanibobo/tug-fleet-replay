# Tug fleet replay — dashboard

Next.js console that replays Port of Los Angeles tug traffic as hybrid-electric telemetry.
Dark, map-first, one headline number: the share of tug-days that ran without the generator at a
given battery size. Independent project; not affiliated with Arc.

## Scripts

| Command | What it does |
| --- | --- |
| `npm run dev` | Dev server at http://localhost:3000 |
| `npm run build` | Production build (type-checks and lints) |
| `npm run start` | Serve the production build |
| `npm run lint` | ESLint |
| `node scripts/make-fixture.mjs` | Regenerate sample data into `public/data/` |

Requires Node 22. Install with `npm install`.

## Env vars

Copy `.env.example` to `.env.local`.

| Var | Default | Meaning |
| --- | --- | --- |
| `NEXT_PUBLIC_DATA_MODE` | `static` | `static` reads `/data/*.json` from `public/` and replays in the browser; `ws` streams from a server |
| `NEXT_PUBLIC_API_URL` | — | REST base for `ws` mode: `GET /fleet`, `GET /summary`, `GET /tugs/{id}/days/{date}` |
| `NEXT_PUBLIC_WS_URL` | — | WebSocket URL for `ws` mode; messages are `{type:"snapshot"|"telemetry", data}` |

The mode is fixed at build time. The component tree is identical in both modes; only `useFleet` differs.

## Modes

- **static**: `src/lib/useFleet.ts` loads `/data/fleet.json` (the compact columnar week), runs a
  `requestAnimationFrame` replay clock at 60x/120x/300x, and interpolates positions between the
  1-minute samples. Play, pause, speed and the week scrubber are all client-side.
- **ws**: fetches `${API_URL}/fleet` for the first snapshot, then applies `snapshot` and `telemetry`
  WebSocket messages. The server owns the clock, so the transport controls are disabled and the panel
  says "Live from server". Reconnects with backoff.

## Data files

Shapes are in `../docs/CONTRACT.md`; TypeScript types in `src/lib/types.ts`.

| Path | Contract section | Used by |
| --- | --- | --- |
| `public/data/fleet.json` | 5 | Fleet map replay |
| `public/data/summary.json` | 4 | Headline, battery slider, About assumptions |
| `public/data/tugdays/{tug_id}/{date}.json` | 3 | Tug day page |
| `public/recordings/{tug_id}/{date}.rrd` | 6 | Rerun inspector (`recording_url` in the tug day file) |

The files shipped in this repo are generated by `scripts/make-fixture.mjs` and carry
`"fixture": true`, which the UI shows as a "Sample data" badge. The Python pipeline in `../pipeline`
produces the real files from NOAA AIS (`python -m tug_replay ...`, see the root README) and writes
them to the same paths with the same shapes; nothing else in the dashboard changes.

Simulated figures are marked once per panel with the footnote "Estimates. Parameters in config.yaml." (`../config.yaml`).

## Layout

```
src/app/            routes: / (fleet), /tugs/[id] (tug day), /about
src/components/     Nav, Panel, BatteryBar, StatusChip, Slider, Stat, Footnote, FixtureBadge, Footer
src/components/fleet/   FleetConsole, FleetMap (MapLibre), ClockPanel, HeadlinePanel, FleetList, TugDetail
src/components/tug/     TugDayView, DayTimeline (SVG), JobsList, TrackMap, RerunInspector
src/components/about/   AboutContent, Architecture (CSS diagram)
src/lib/            types, env, format, useFleet, useTugDay, useSummary, useAnimatedNumber
scripts/            make-fixture.mjs
```

Styling is plain CSS modules plus `src/app/globals.css`, which holds the tokens from
`../docs/DESIGN.md`. Font: Inter Tight via `next/font/google`. Map style: Carto dark matter with the
water tinted toward `--sea`. The Rerun viewer (`@rerun-io/web-viewer-react@0.38.1`, matching the
Python SDK) is imported with `next/dynamic` only when the inspector opens.
